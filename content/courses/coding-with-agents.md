**Purpose.** The developer's job is shifting from writing every line to directing something that
writes lines and reviewing what it produces. This is the two days that make that shift practical
rather than theoretical.

**Contains.**
- What a coding agent actually is: a loop of plan, edit, run, observe, repeat, with tools. Why that
  loop, and not autocomplete, is what changes the work
- **Context engineering**, the core skill of the course. Agents fail on real codebases for the same
  reasons new hires do: undocumented conventions, decisions buried in old commits, dependencies
  across repos. What to put in front of an agent and what to leave out
- Repo hygiene as a force multiplier: a project file that states conventions, clear structure,
  tests that actually run. Disorganised repos produce bad agent output, and that is fixable
- Writing the task: acceptance criteria up front, scope small enough to verify, when to ask for a
  plan before any edit
- The tools, hands-on, with their differences named rather than ranked. Claude Code in the terminal,
  Codex, Kiro's spec-driven approach, Claude Design for interface work
- Reviewing agent output: what to check first, the failure patterns worth knowing (plausible but
  wrong, silently dropped requirements, tests written to pass rather than to test)
- Where to stop. Tasks worth delegating, tasks worth doing yourself, and how to tell before you
  have burned an hour
- Cost and speed awareness: why an agent run is not free and what drives the number
- Labs run against a real repository, not a toy example
